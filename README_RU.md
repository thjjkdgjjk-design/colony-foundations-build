# Colony Foundations — экспериментальная колония для Fabric 1.21.5

Цель сборки: Minecraft 1.21.5, Fabric Loader и Fabric API. Сборка выполняется на JDK 22, но байткод выпускается для Java 21, а метаданные допускают Java 21+ — это соответствует требованиям Minecraft 1.21.5.

## Интерфейс строительства
- ПКМ по ратуше открывает каталог построек — вводить команды не нужно.
- Встроена стартовая схема коттеджа.
- Дополнительные постройки загружаются из совместимых datapack, на использование и распространение которых у вас есть необходимые права.
- Перед запуском можно повернуть чертёж на 0°, 90°, 180° или 270°.
- Заказ, выбранная схема, поворот и прогресс сохраняются в NBT ратуши.
- Кнопка «Пауза / продолжить» управляет строительством из интерфейса.
- Обычного жителя назначает строителем контракт из мода.
- При занятой позиции, выходе за границу мира, недопустимой высоте или незагруженном чанке заказ приостанавливается с указанием причины и координат; прогресс и ресурсы не расходуются для заблокированного блока.

## Импорт чертежей
Загрузчик читает собственные JSON-чертежи Colony Foundations и сжатые NBT-файлы формата Structurize v1 с палитрой блоков и упакованным массивом. Публичная сборка временно не скачивает и не включает оригинальные NBT-схемы MineColonies: для закреплённой ревизии не подтверждено явное разрешение на распространение этих файлов. Можно установить совместимый datapack со схемами, использование и распространение которого разрешено его лицензией. Подробности — в THIRD_PARTY_NOTICES.md.

Для безопасности импортируются только блоки и состояния блоков. Данные блок-сущностей, сущности, специальные блоки-подстановки Structurize и команды из оригинальных схем не исполняются. Если в мире отсутствует блок из другого мода, он заменяется воздухом. Пустые клетки оригинального чертежа не удаляют существующие блоки игрока.

## Чего пока нет
Это не полный порт MineColonies или Structurize. Пока отсутствуют все профессии и их ИИ, склады и экономика, этапы повышения уровня здания со снабжением, полноценный предпросмотр-призрак как в Structurize, редактор чертежей, все стили и типы построек. Интерфейс и размещение схем — следующий фундамент для дальнейшей работы, но игровое тестирование всё ещё нужно.

## Установка
1. Скачай последний JAR из GitHub Releases.
2. Удали предыдущую версию Colony Foundations из .minecraft/mods, чтобы не было дубликатов.
3. Установи Fabric Loader и Fabric API для Minecraft 1.21.5.
4. Проверь в новом творческом мире или копии мира: поставь ратушу, назначь жителя контрактом и выбери встроенный коттедж. Для других построек сначала установи совместимый datapack со схемами, на которые распространяется лицензия, разрешающая такое использование.

## Команды управления колонией (экспериментально)

Владелец может управлять колонией ратуши, находясь не дальше 8 блоков от неё. Команды выполняются на сервере и ищут ратушу в текущем измерении игрока:

- `/colony info <x> <y> <z>` — показать название, владельца, уровень и число участников (владелец/участник).
- `/colony rename <x> <y> <z> <новое имя>` — переименовать колонию (только владелец).
- `/colony invite <x> <y> <z> <игрок>` — добавить участника (владелец или участник с правом `manage_members`; игрок должен быть в сети). Новому участнику права действий не выдаются автоматически.
- `/colony revoke <x> <y> <z> <игрок>` — отозвать доступ (владелец или участник с правом `manage_members`; игрок должен быть в сети).
- `/colony permission <x> <y> <z> <игрок> <действие> <true|false>` — владелец меняет одно из прав: `break_blocks`, `place_blocks`, `use_blocks`, `manage_members`, `build_projects`, `assign_workers`.

Это промежуточный интерфейс управления, а не полная совместимость с системой прав MineColonies. Для этой функции ещё нужны сборка/CI и внутриигровая проверка в мультиплеере.


### Ранги и права колонии (частичный перенос)

- `/colony rank <x> <y> <z> <игрок онлайн> <officer|friend|neutral|hostile>` назначает ранг участнику.
- `/colony rank-permission <x> <y> <z> <ранг> <действие> <true|false>` меняет действие для всех текущих и будущих участников ранга.
- `/colony permission <x> <y> <z> <игрок> <действие> <true|false>` сохранена как совместимая команда, но теперь изменяет профиль ранга участника — изменение затрагивает всех с тем же рангом.
- Поддерживаемые локальные действия: `break_blocks`, `place_blocks`, `use_blocks`, `manage_members`, `build_projects`, `assign_workers`.

Ранги `OWNER/OFFICER/FRIEND/NEUTRAL/HOSTILE` и их профили сохраняются. Это ещё не полный перенос прав MineColonies: другие действия, союзы/враждебность и GUI ратуши не реализованы. Старые сохранения без версии прав переводят существующих участников в `officer` для сохранения прежнего доступа; промежуточный формат сохраняет индивидуальные права до явного изменения профиля соответствующего ранга.


### Постоянный журнал строительных заказов (экспериментально)

Текущий заказ BUILD из ратуши теперь дублируется в постоянный реестр колонии: сохраняются ID заказа, схема, площадка, поворот, инициатор, статус, прогресс и причина блокировки. Команда `/colony work-orders <x> <y> <z>` рядом с ратушей показывает журнал (нужно право `build_projects`). Это основа хранения и истории, а не полноценная очередь: BUILD по-прежнему выполняется одним существующим исполнителем ратуши; настоящее выполнение UPGRADE, REPAIR и REMOVE, параллельные заказы, планирование по приоритету и модули зданий ещё не реализованы.


### Очередь заказов BUILD (экспериментально)

- `/colony queue <x> <y> <z> <blueprint_id> <rotation 0-3> <offset_x> <offset_z> <priority -10..10>` добавляет ещё один заказ BUILD, не заменяя текущую стройку.
- Когда ратуша простаивает либо текущий BUILD завершён, следующий BUILD выбирается по приоритету; при равном приоритете порядок определяется последовательностью создания. Один строительный исполнитель использует общий склад ратуши, а расчёт необходимых материалов учитывает текущие и поставленные в очередь BUILD.
- Очередь пока исполняет только BUILD. Для UPGRADE, REPAIR и REMOVE есть модель состояний/уровней, но нет реального исполнителя размещения. Сделайте резервную копию мира; CI не заменяет тестирование непосредственно в Minecraft.

- `/colony order-priority <x> <y> <z> <sequence> <priority -10..10>` меняет приоритет ожидающего заказа без прогресса.
- `/colony order-cancel <x> <y> <z> <sequence>` отменяет только queued/blocked заказ с нулевым прогрессом; активный/начатый заказ отменить этой командой нельзя.
