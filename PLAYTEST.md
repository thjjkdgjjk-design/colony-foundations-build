# PLAYTEST — Colony Foundations / Colony Schematics

Этот сценарий предназначен для **проверки тестовой сборки в Minecraft**, а не для подтверждения полного порта MineColonies. Создайте новый тестовый мир или копию мира: строительство и размещение схем могут менять большие области и не имеют полноценной системы отката.

## 1. Версии и установка

Целевая среда проверена в конфигурации сборки проекта:

- Minecraft Java Edition **1.21.5**.
- Fabric Loader **0.16.14 или новее** для Minecraft 1.21.5.
- Fabric API **0.119.5+1.21.5** или совместимая версия для Minecraft 1.21.5.
- CI собирает проект с JDK **22**. В метаданных мода указан минимум Java 21, а байткод целевой версии Java 21; Java 22 подходит для этого тестового профиля.

Официальные страницы зависимостей: [Fabric Installer](https://fabricmc.net/use/installer/), [Fabric API для Minecraft 1.21.5 — файл 0.119.5+1.21.5](https://www.curseforge.com/minecraft/mc-mods/fabric-api/files/6342901), [Temurin JDK 22](https://adoptium.net/temurin/releases/?version=22).

1. Установите Fabric Loader для **Minecraft 1.21.5** и один раз запустите профиль Fabric, чтобы создать папки.
2. Скачайте из [GitHub Releases этого проекта](https://github.com/thjjkdgjjk-design/colony-foundations-build/releases) файл `colony-foundations-fabric-1.21.5-0.1.0-alpha.1.jar` и поместите его в папку `.minecraft/mods`. Выбирайте самый новый release с зелёным успешным CI-run; не используйте исходники JAR (`*-sources.jar`) вместо игрового мода.
3. Положите JAR Fabric API для Minecraft 1.21.5 в ту же папку `mods`.
4. Не кладите туда две версии Colony Foundations одновременно. Удалите предыдущую версию мода перед заменой.
5. Запустите игру, выбрав профиль Fabric 1.21.5. Создайте новый мир **Creative**, включите читы и держите копию мира на случай ошибки.

### Необязательный аддон схем

Для отдельного тестирования каталога/сканирования установите также `colony-schematics-fabric-1.21.5-0.1.0-alpha.1.jar` из того же release. Это **отдельный самостоятельный мод** с ID `colony_schematics`, он не требуется для загрузки основной колонии. Для тестирования в одиночном мире JAR достаточно в папке `mods`; на выделенном сервере сетевая функция аддона требует установить его на сервер и на подключающиеся клиенты. Fabric API нужен в обоих случаях.

## 2. Проверка запуска и регистрации контента

1. В главном меню откройте **Mods** и убедитесь, что отображается мод Colony Foundations. При установленном аддоне отдельно должен отображаться Colony Schematics.
2. В новом творческом мире выполните:
   ```mcfunction
   /give @s colony_foundations:town_hall 1
   /give @s colony_foundations:builder_contract 1
   /give @s colony_foundations:worker_contract 1
   ```
3. Убедитесь, что команды не сообщают об отсутствующих предметах. Поставьте ратушу на ровной свободной площадке. Размещение ратуши текущим кодом закрепляет колонию за разместившим игроком.
4. Запишите координаты блока ратуши (F3). Все команды ниже используют именно позицию блока `x y z`, а не позицию игрока; для интерфейса команд владелец должен находиться не дальше 8 блоков от ратуши.

Ожидаемый результат: игра остаётся в мире без экрана ошибки Fabric, ратуша отображается, а команда ниже показывает имя колонии и владельца:

```mcfunction
/colony info <x> <y> <z>
```

В командах замените `<x> <y> <z>` на три числа координат, например `100 64 -20`. Не вводите угловые скобки буквально.

## 3. Каталог чертежей и строительство

1. Правой кнопкой мыши откройте ратушу. Должно открыться окно каталога/управления строительством.
2. Встроенная тестовая схема — `colony_foundations:cottage` (стартовый коттедж). Официальные схемы MineColonies не встроены в этот JAR: их распространение для закреплённого набора файлов не подтверждено.
3. Положите рядом с ратушей ванильного жителя. Удерживая `builder_contract`, щёлкните правой кнопкой по жителю. При успешном назначении появится сообщение о строителе и имя жителя изменится на «Строитель». Если житель уже назначен на другую роль, сначала используйте свободного жителя.
4. В интерфейсе ратуши выберите `Стартовый коттедж`, при необходимости поменяйте поворот/смещение площадки и нажмите **«Строить»**. Если стройка остановлена из-за материалов, откройте инвентарь/интерфейс материалов, добавьте указанные предметы и используйте **«Снабдить»**. Оставьте строителя и ратушу в доступной загруженной области.
5. Наблюдайте за статусом/счётчиком прогресса и появлением блоков. Запишите предупреждения о недостающих материалах, препятствиях или неизвестных блоках.

Ожидаемый результат: запрос принят, схема/позиция/поворот записываются и прогресс строительства обновляется по мере размещения блоков. Не ожидайте полного строителя MineColonies: текущий исполнитель использует только частично реализованную механику строительства.

## 4. Сохранённая очередь BUILD и команды

Выполняйте это в том же тестовом мире. В примерах ратуша стоит на `100 64 -20`; замените координаты на свои. Смещения площадок — относительно ратуши; используйте свободную ровную область внутри территории.

1. Добавьте тестовый заказ:
   ```mcfunction
   /colony queue 100 64 -20 colony_foundations:cottage 0 20 0 5
   ```
   Если площадка вне территории, пересекается с завершённой постройкой/другим активным заказом или схема недоступна, заказ должен быть отклонён с сообщением.
2. Посмотрите журнал:
   ```mcfunction
   /colony work-orders 100 64 -20
   ```
   В выводе запишите номер `#sequence`, статус, схему, прогресс и площадку.
3. Чтобы проверить сортировку, когда первый BUILD уже активен или есть ожидающие заказы, добавьте второй заказ с другим смещением и приоритетом. Приоритет допустим от `-10` до `10`; большие числа имеют более высокий приоритет, при равных приоритетах действует последовательность создания.
4. Меняйте приоритет **только у ожидающего заказа без прогресса**:
   ```mcfunction
   /colony order-priority 100 64 -20 <sequence> 8
   ```
5. Проверьте отмену отдельного ожидающего заказа с нулевым прогрессом:
   ```mcfunction
   /colony order-cancel 100 64 -20 <sequence>
   ```
   Активный или уже начатый заказ этой командой отменяться не должен.
6. Повторите `/colony work-orders 100 64 -20` и сравните статусы.

Ожидаемый результат: BUILD-заказы сохраняются в журнале, для допустимого ожидающего заказа меняется приоритет, заказ с нулевым прогрессом можно отменить. REPAIR также исполняется, но только для ранее зарегистрированного завершённого здания из доступного датапака. UPGRADE и REMOVE пока не имеют исполнителя.

## 5. Ограниченный ремонт REPAIR

REPAIR работает только для здания, которое уже было построено и зарегистрировано в постоянном каталоге как blueprint-постройка. Это не команда для произвольных ванильных зданий.

1. Создай резервную копию тестового мира. Убедись, что используемый blueprint datapack установлен и доступен после /reload.
2. В примере ниже ратуша находится на 100 65 -20, а anchor зарегистрированной постройки — на 100 64 -20. Замени обе позиции своими координатами:
```mcfunction
/colony repair 100 65 -20 100 64 -20 5
/colony work-orders 100 65 -20
```
   Значение 5 — приоритет от -10 до 10. Эта ограниченная реализация требует, чтобы Y якоря здания был ровно на один блок ниже ратуши; иначе команда должна отклонить заказ.
3. В копии мира сломай несколько блоков внутри зарегистрированной постройки, но не ломай её якорь. Команда принимает схему только при совпадении сохранённых ID, поворота, уровня и габаритов.
4. Дождись строителя. Отсутствующие или заменяемые клетки должны восстанавливаться, корректные блоки пропускаться. Если целевая клетка занята прочным несовпадающим блоком, работа должна приостановиться и не перезаписать его автоматически.
5. Перезапусти мир и проверь статус заказа командой work-orders.

Ограничение: REPAIR использует общий исполнитель строительства и склад ратуши; это не полноценная MineColonies система требований, модулей зданий или ремонта всех типов сооружений. UPGRADE и REMOVE пока не исполняются.
## 6. Имя колонии, права и перезапуск

1. Проверьте переименование:
   ```mcfunction
   /colony rename 100 64 -20 Test Colony
   /colony info 100 64 -20
   ```
2. Перезапустите игру, откройте тот же мир и проверьте имя колонии, ратушу, журнал заказов, завершённые записи построек и продолжение незавершённого строительства.
3. Для проверки прав нужен **второй игрок** в локальном/выделенном сервере. Участник сам по себе не должен автоматически иметь все права территории. Точные команды для ранга и разрешений:
   ```mcfunction
   /colony invite <x> <y> <z> <player>
   /colony rank <x> <y> <z> <player> officer
   /colony rank-permission <x> <y> <z> friend break_blocks true
   /colony permission <x> <y> <z> <player> build_projects false
   /colony revoke <x> <y> <z> <player>
   ```
   Ранги в этой промежуточной версии: `officer`, `friend`, `neutral`, `hostile`; допустимые действия: `break_blocks`, `place_blocks`, `use_blocks`, `manage_members`, `build_projects`, `assign_workers`. Команда `permission` в текущей версии редактирует профиль ранга участника, поэтому изменение может затронуть остальных участников того же ранга.

Ожидаемый результат: имя и рабочие данные остаются доступны после сохранения/загрузки; в мультиплеере сервер отклоняет действия без нужного разрешения. Внутриигровое сохранение/перезапуск и многопользовательские права ещё требуют реальной проверки — CI не запускает клиент Minecraft.

## 7. Дополнительный аддон Colony Schematics (необязательно)

Проверяйте эту секцию только после установки отдельного JAR аддона.

1. В Creative откройте предметы группы **Functional** и возьмите **Инструмент чертежей**. Альтернатива:
   ```mcfunction
   /give @s colony_schematics:schematic_tool 1
   ```
2. Щёлкните инструментом правой кнопкой мыши **в воздухе** — откроется каталог. Без совместимого датапака каталог может быть пустым.
3. Для сканирования небольшой тестовой конструкции наведите инструмент на блок первого угла и щёлкните правой кнопкой, затем аналогично выберите противоположный угол. Если область допустимого размера и чанки загружены, аддон создаст **Свиток чертежа**.
4. В Creative щёлкните свитком по блоку в свободной области, чтобы разместить копию сканированной структуры. Перед этим убедитесь, что копия не затронет вашу постройку: у аддона нет полноценного отката, а размещение может менять блоки мира.
5. Для проверки внешнего каталога используйте только совместимый datapack, на распространение которого у вас есть права. ZIP датапака поместите в `<minecraft>/saves/<имя мира>/datapacks/`, затем выполните `/reload` или заново откройте мир. Схемы каталогизируются под `data/colony_schematics/blueprints/`.

Ожидаемый результат: инструмент открывает экран каталога, сканер выдаёт переносимый свиток, а свиток ставит отсканированную схему в Creative. Поворот/зеркалирование и сложные block entities/сущности требуют отдельной регрессионной проверки.

## 7. Частичная профессия лесоруба

1. В новом тестовом мире выдай хижину, контракт и топор:
```mcfunction
/give @s colony_foundations:hut_lumberjack 1
/give @s colony_foundations:worker_contract 1
/give @s minecraft:stone_axe 1
```
2. Поставь хижину внутри территории основанной колонии. Недалеко от неё, также внутри территории, должно стоять обычное дерево: вертикальный ствол из 3–32 log-блоков на поддерживаемой почве (земля, трава, подзол и другие ограниченные ванильные почвы), с листьями возле верхушки.
3. Открой хижину пустой рукой и положи топор в её инвентарь. Удерживая worker_contract, нажми ПКМ по хижине, чтобы назначить свободного жителя.
4. Подожди несколько секунд. Лесоруб должен подойти к дереву и убирать верхний log-блок за одно действие, помещая соответствующий предмет лога в инвентарь хижины. Если инвентарь заполнен, рубка должна остановиться.
5. Сохрани и перезапусти мир во время рубки. После загрузки хижина должна сохранять координату основания текущего дерева; если дерево ещё существует и доступно, работа должна продолжиться.

Это первый ограниченный рабочий цикл, а не полная профессия MineColonies: нет обхода ветвей, срубки листьев, сбора/посадки саженцев, поддержки модовых деревьев и расхода прочности топора. Автоматический CI не является внутриигровой проверкой.
## 8. Что пока не реализовано / ограничения

- Это тестовая альфа-версия, **не полный функциональный порт MineColonies**.
- Большинство блоков-хижин пока используют безопасные модель/текстуру на основе дубовых досок; наличие блока в инвентаре не означает, что реализована соответствующая профессия.
- Нет полного набора оригинальных блоков, предметов, рецептов, моделей, анимаций и текстур; оригинальные схемы MineColonies не входят в поставку. Не устанавливайте Forge/NeoForge-библиотеки как зависимости Fabric-мода.
- Профессии, ИИ, логистика, экономика, исследования, рейды, уровни/модули зданий и оригинальная система GUI реализованы только частично или отсутствуют.
- Очередь исполняет BUILD и ограниченный REPAIR для ранее зарегистрированных завершённых схемных построек; UPGRADE и REMOVE пока не имеют исполнителя. Полноценная клиентская ghost-модель, survival-материалы, отмена/undo-redo и полная миграция Structurize не реализованы.
- Аддон схем отдельный; он не превращает набор чертежей в полноценные здания MineColonies. Отсутствующие блоки из других модов могут заменяться воздухом.
- В среде разработки можно запускать Gradle/JUnit и проверять состав JAR через CI; реальный игровой клиент и выделенный сервер не были запущены автоматически. Не отмечайте сценарий как проверенный в игре, пока он не пройден вручную.

## 9. Если тест не проходит

1. Сразу после вылета не перезапускайте игру несколько раз: сначала сохраните логи.
2. Пришлите `logs/latest.log` и, если он создан, файл из `crash-reports/`.
3. Укажите версию Minecraft, версию Fabric Loader, версию Fabric API, список JAR в `mods`, одиночная это игра или сервер, шаг сценария и последние сообщения чата.
4. Для клиентского профиля стандартный путь на Windows: `%appdata%\.minecraft\logs\latest.log`. Если лаунчер использует отдельную папку игры, ищите `logs/latest.log` внутри неё. На выделенном сервере — `logs/latest.log` в каталоге сервера.

Спасибо: скриншоты с координатами ратуши/экрана и точная команда перед ошибкой помогут воспроизвести сценарий.
